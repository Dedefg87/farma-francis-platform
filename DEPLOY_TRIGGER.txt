Deploy trigger: 2026-07-16 23:05:00 -03
Fix: Client profile pictures now resolve via Evolution API proxy instead of direct CDN fetch

Root cause: previous profile-pic.ts did fetch(pictureUrl) directly on WhatsApp CDN
(pps.whatsapp.net), which is hotlink-protected and returns 403 even server-side.
Now uses downloadWhatsAppMediaFromEvolution (Evolution instance proxy) to obtain
the bytes, then uploads to R2 and stores the permanent public URL.

Lazy-loads on getConversations so ALL existing customers get their photo resolved
retroactively the moment the inbox is opened.

Note: the 404s in console are for OLD document PDFs (comprovantes) uploaded before
the R2 fix — separate issue, not profile photos.
